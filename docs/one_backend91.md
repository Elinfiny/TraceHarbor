## Exact future-client representation

The only supported client seam is request(method, repository-relative-path,
JSON-request-object) returning Reply(status, body: bytes, media_type, eof).
media_type identifies the explicitly negotiated representation, not a guessed
representation or native authority. It is exactly application/vnd.github+json,
or application/vnd.github.raw+json for a blob GET only. No real authenticated
client is installed by this source. Actual original Reply objects and complete
wire bytes are retained privately before parsing or projection.

Every reply is bounded to 65536 bytes and must have eof=True. JSON is strict
UTF-8 with no duplicate keys, nonfinite numbers, trailing non-JSON data or
non-object envelope. The tree must contain exactly one nonsymlink 100644 blob
with the exact path/SHA and truncated=False. Optional size must be an integer
(not Boolean) equal to the complete record length. Known url/node_id metadata
is explicitly validated; URLs must name the exact repository/object, node IDs
are bounded ASCII strings. Unexpected semantic fields are refused. The module
projects only after retaining and validating the full reply, then independently
computes the Git tree object ID from the exact semantic entry.

The observed repository tree a3edd56e4afee71ca17ff97f373fd572a50d64cc has entries
with path/mode/type/sha/size/url, matching GitHub's documented tree response:
https://docs.github.com/en/rest/git/trees . The fixture uses that actual shape
with size and URL derived from its own synthetic record, never copied evidence
or a claimed native vendor execution.

The documented JSON blob envelope contains base64 content, encoding, size and
SHA, with bounded optional url/node_id. Candidate92 accepts canonical base64,
optionally in 60-column LF/CRLF lines plus one final terminator. This is the
explicit bounded client contract; wrapping was not observed in an actual raw
blob envelope by the Auditor. No spaces, tabs, stray CR, nonalphabet bytes,
noncanonical padding, invalid UTF-8 or arbitrary whitespace are ignored. The
separately negotiated raw media form uses complete raw bytes, never guessed
from the body. Both routes compare the entire expected record bytes, size and
computed Git blob SHA. Reference: https://docs.github.com/en/rest/git/blobs .

Capture errors retain actual original objects and ordered private secondary
exception objects. A primary call/parse/expiry failure remains sticky; a
capture failure cannot replace it or permit another create. Diagnostics remain
local inert evidence, not an independently qualified durable capture sink.
